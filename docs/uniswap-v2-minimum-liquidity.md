# Uniswap V2 首池为什么锁 1000

首笔加池时，Pair 把 **1000 枚 LP** 铸给 `address(0)`。这是 `MINIMUM_LIQUIDITY = 10**3`，单位是 LP 的最小单位（wei），不是每种底层代币各 1000 个。

这 1000 枚谁也转不走、烧不掉。它把 LP 总供给的下限钉在 1000，用来挡住捐赠攻击：攻击者先占住极少份额，再把代币直接转进池子抬高单价，让下一笔存款按整数除法铸出 0 份额，然后把自己那一点 LP 烧掉、把别人的钱提走。没有这 1000 时，捐赠只是临时占用的本金，赎回时会回到攻击者手里。锁住以后，要把后来者打成 0 份额，捐赠大约得是存款的 1000 倍；攻击者若只给自己留 1 LP，这笔捐赠里的 1000/1001 永久留在 `address(0)`，攻击亏本。

代码在 `src/uniswapv2/UniswapV2Pair.sol` 的 `mint`。同一件事的面试简答在 `docs/uniswap-v2-v3-v4-interview.md` 第 6 题。ERC-4626 金库上的同一类攻击见 `src/erc-4626/inflation-attack.md`。

## 锁的是 LP，不是两种代币各 1000

```solidity
uint public constant MINIMUM_LIQUIDITY = 10**3;
```

`totalSupply == 0` 时走首池分支：

```text
liquidity = sqrt(amount0 * amount1) - 1000
_mint(address(0), 1000)   // 永久锁住
_mint(to, liquidity)      // 加池的人拿到剩下的
```

`sqrt(amount0 * amount1)` 必须大于 1000，否则 `.sub(MINIMUM_LIQUIDITY)` 下溢回滚。两边数量相等时，每种至少要存 1001 wei，加池的人才能拿到 1 LP。

LP 合约 `UniswapV2ERC20` 的 `decimals` 是 18。链上余额就是整数 1000。钱包按 18 位小数显示时，它是 `0.000000000000001` LP，很容易被看成「锁了 1000 个代币」。

两边存入量相等、各为 `A`（`A > 1000`）时，死掉的份额占 `1000 / A`。它对应的底层资产是：

```text
每种代币锁住的数量 = A * (1000 / A) = 1000 wei
```

所以正常首池里，永久留下的只是每种代币 1000 wei，外加这点尘埃以后按比例分到的手续费。两种 18 位小数代币各存 1 个时，`A = 10**18`，锁住的比例是 `1000 / 10**18`。

两边数量不相等时，锁住的不再是两边各 1000 wei。设首池铸出的总 LP 为 `L = sqrt(amount0 * amount1)`，死份额占 `1000 / L`，两种代币按这个比例留下。

## 之后的份额按储备整除

首池之后，`mint` 不再用平方根：

```text
liquidity = min(amount0 * totalSupply / reserve0,
                amount1 * totalSupply / reserve1)
```

除法向下取整。`totalSupply` 相对 `reserve` 越小，同样一笔存款越容易被抹成 0。

`burn` 只销毁 Pair 合约自己持有的 LP：调用方先把 LP 转进 Pair，再按 `balanceOf[address(this)]` 烧掉。`address(0)` 没有私钥，那 1000 枚转不回来，也就烧不掉。`totalSupply` 在第一次 `mint` 之后永远至少是 1000，首池分支不会再进。

## 没有这 1000 时，捐赠可以原路收回

份额公式是 `assets * totalSupply / reserve`。空池上第一次存款若按 `sqrt` 且不扣 1000，攻击者可以各存 1 wei，拿到 1 LP。然后把代币直接 `transfer` 进 Pair（不调用 `mint`）。`mint` 用「余额 − 储备」记账，直接转账不会铸 LP；下一次 `mint` / `burn` / `sync` 才会把这笔余额写进储备。单价上去了，总供给还是 1。

下面受害者每种代币存 5。攻击者要让 `5 * 1 / reserve < 1`，所以把每种储备抬到 6 以上，捐赠 5 就够。

| 步骤 | 每种储备 | totalSupply | 结果 |
| --- | ---: | ---: | --- |
| 攻击者各存 1 | 1 | 1 | 攻击者持有唯一的 1 LP |
| 攻击者每种再转入 5 | 6 | 1 | 不铸 LP。1 LP 对应 6 枚代币 |
| 受害者每种存 5 | 11 | 1 | `5 * 1 / 6 = 0` LP，两种代币各 5 枚已在池里 |
| 攻击者烧掉 1 LP | 0 | 0 | 按 100% 份额提走 11 |

攻击者投入 `1 + 5 = 6`，提走 11，利润 5，等于受害者的本金。捐赠在 `burn` 时回到自己手里，只是临时垫资。把受害者打成 0 份额的条件是储备大于 `存款 × totalSupply`。`totalSupply = 1` 时，捐赠量和能偷到的金额同一量级。

## 锁住以后，同一笔攻击亏的是 1000 倍

攻击者仍想只留 1 枚可烧毁的 LP。首池要先满足 `sqrt = 1001`，两边相等时就得各存 1001，其中 1000 铸给 `address(0)`，自己只留 1。此时 `totalSupply = 1001`。

受害者仍每种存 5。要让 `5 * 1001 / reserve < 1`，每种储备必须大于 `5 * 1001 = 5005`。池子里已经有 1001，所以还要每种再转入 `1001 * 5 = 5005`。

| 步骤 | 每种储备 | totalSupply | 结果 |
| --- | ---: | ---: | --- |
| 攻击者各存 1001 | 1001 | 1001 | `address(0)` 持有 1000，攻击者持有 1 |
| 攻击者每种再转入 5005 | 6006 | 1001 | 不铸 LP |
| 受害者每种存 5 | 6011 | 1001 | `5 * 1001 / 6006 = 0` LP |
| 攻击者烧掉自己的 1 LP | 6005 | 1000 | 只提走 `6011 / 1001 = 6` |

攻击者投入 `1001 + 5005 = 6006`，提走 6，净亏 6000。这 6000 留在池子里，对应剩下的 1000 枚死 LP，谁也提不走。受害者的 5 也在这 6005 里面。

一般地，攻击者只给自己留 1 LP、受害者每种存 `D`（`D < 1001`）时：

```text
需要捐赠的每种数量 ≈ 1001 * D
攻击者提回 ≈ D + 1
净亏 = 1000 * (D + 1)
```

亏掉的部分就是死份额占走的本金。把攻击者自己的 LP 铸得很大也补不回来：死的始终是 1000 枚，要把后来者整除成 0，捐赠仍得覆盖「约 1000 倍存款」里属于 `address(0)` 的那一截，这一截赎回时不会回到攻击者地址。

## 池子因此抽不空

全体可流通 LP 都烧掉之后，储备还按 `1000 / totalSupply` 留在 Pair 里。比例和抽干前一样，现货价格不会因为这次 `burn` 被改成任意值。

若这 1000 不存在，最后一枚 LP 可以把两种储备都取光，`totalSupply` 回到 0。下一笔 `mint` 会再次走进首池公式，存入比例由调用方随意决定，池子价格被重新定价。死 LP 把这条路径堵上。`UniswapV2Pair` 里那句「防完全抽空池子把价格操纵成任意值」指的是这件事。

## 这 1000 不负责的事

它抬的是「份额相对储备」的下限，专门让「铸出 0 LP 再整池提走」亏本。大池子上，存款仍会因向下取整少拿不到 1 LP 的零头，零头按比例归当时的股东，其中也有 `address(0)` 那 1000 枚。

直接往 Pair 转账依然会抬高余额。下一次 `mint`、`burn` 或 `sync` 会把差额写进储备，老 LP 按份额分享。这是池子接收捐赠的方式，不是这 1000 要禁止的行为。

现货价格在单笔 `swap` 里可以被大单推动。那取决于池子深度和 0.3% 手续费，不取决于首池锁了多少 LP。

## 面试怎么答

问的是「首池为什么锁 1000」。先用下面这段说完，再等追问。数字不用背整张表，记住一句：不锁时，捐赠和能提走的钱是同一量级；锁住以后，捐赠大约是存款的 1000 倍，而且大部分提不回来。

首池 `liquidity = sqrt(amount0 * amount1) - 1000`，这 1000 枚 LP 铸给 `address(0)`，永久拿不回来。之后加池按 `amount * totalSupply / reserve` 向下取整。总供给如果可以小到 1，攻击者先占 1 LP，再直接把代币转进 Pair 把储备抬高，下一笔存款会整除成 0：币进了池子，份额是 0，攻击者烧掉那 1 LP 就把钱提走，捐赠也一起收回。锁住 1000 以后，总供给至少是 1000。要把后来者打成 0 份额，捐赠得大约是存款的 1000 倍；攻击者若只给自己留 1 LP，其中 1000/1001 留在死份额上，攻击亏本。两边数量相等时，诚实首池实际锁住的底层资产每种只有 1000 wei。

追问再补这三句：

1. 1000 的单位是 LP 的 wei。LP 有 18 位小数，钱包里显示成 `0.000000000000001`，不是每种代币 1000 个。`sqrt(amount0 * amount1)` 必须大于 1000，否则首池 `mint` 回滚。
2. `burn` 只烧 Pair 自己持有的 LP。`address(0)` 转不出这 1000 枚，所以 `totalSupply` 不会回到 0，池子也抽不空，不能清空后再用首池公式随意重定价。
3. 它让「铸出 0 LP 再整池提走」亏本。直接往池子转账仍然合法，大单仍然可以推动现货价。交易手续费里的 `997/1000` 是另一件事，和这 1000 枚 LP 无关。
